# Отчет: разходи и приходи

Локална програма, която чете продажбите от базата на Microinvest Склад Про (SQL Server)
и ги показва по дни заедно с ръчно въведените разходи.

## Стартиране

Нужен е Node.js 20.12 или по-нов.

    npm install      # веднъж, инсталира драйвера за SQL Server (mssql)
    npm start        # работа с базата на Microinvest
    npm run demo     # демо с примерни данни, без база

Отворете http://localhost:3000.

## Публикуване на демо в Render

В хранилището има `render.yaml` за Render Blueprint. Качете проекта в GitHub,
в Render изберете **New +** → **Blueprint**, свържете хранилището и приложете
конфигурацията. Render ще стартира `npm run demo`; адресът на приложението ще
се появи в таблото на услугата.

Демо режимът използва примерни данни и не се свързва с база. Всички
посетители виждат и редактират едни и същи данни. Файловата система на безплатната
услуга е временна, затова направените промени може да се загубят при рестарт или
ново публикуване. Не въвеждайте реални данни.

## Първоначална настройка

Програмата трябва да работи на същия компютър като SQL Server. Тя само чете от базата:
таблиците `Operations`, `Goods` и `GoodsGroups`.

1. **Потребител само за четене.** В SQL Server Management Studio изпълнете (сменете паролата
   и името на базата):

   ```sql
   USE [master];
   CREATE LOGIN [payroll_report] WITH PASSWORD = N'<силна парола>', CHECK_POLICY = ON;

   USE [<базата на Склад Про>];
   CREATE USER [payroll_report] FOR LOGIN [payroll_report];
   GRANT SELECT ON dbo.Operations  TO [payroll_report];
   GRANT SELECT ON dbo.Goods       TO [payroll_report];
   GRANT SELECT ON dbo.GoodsGroups TO [payroll_report];
   ```

   В свойствата на сървъра (Properties → Security) трябва да е избрано
   „SQL Server and Windows Authentication mode“.
2. **TCP/IP.** В SQL Server Configuration Manager → SQL Server Network Configuration →
   Protocols включете **TCP/IP** и рестартирайте услугата SQL Server. Ако инстанцията е
   именувана (напр. `SQLEXPRESS`), пуснете и услугата **SQL Server Browser** или задайте
   порта в `.env`.
3. **Файл `.env`.** Копирайте `.env.example` като `.env` до `server.js` и попълнете сървъра,
   базата, потребителя и паролата. Файлът не се качва в git и паролата не се вижда от браузъра.
4. Стартирайте с `npm start` и отворете **Настройки**. Там се вижда към коя база е свързана
   програмата. Основните групи се свързват с колоните автоматично при първата връзка:
   `AES…` → Сервиз, `AEU…` → Прима карти, `AET…` → Телефони, `AER…` → Стока. Подгрупите
   наследяват колоната на основната група по кода си. Продажбите на артикули без група
   отиват в колоната по подразбиране (Стока).

Сумите са по реалната продажна цена от документа (`Operations.PriceOut` + ДДС), включително
цените, сменени в панела за продажба.

## Инсталиране на сървъра (услуга + Tailscale)

Програмата няма собствени пароли, затова не я отваряйте към интернет. Достъпът е само
през Tailscale, а самата програма слуша само на `127.0.0.1`.

1. В `.env` задайте `PORT=3001`, `HOST=127.0.0.1` и администраторите (вижте `.env.example`):

       ADMINS=ivan@example.com,maria@example.com

   Това са акаунтите, с които хората влизат в Tailscale. Програмата разбира кой е влязъл
   от `tailscale serve` и пуска само тези акаунти; всички останали виждат „Нямате достъп“.
   Директно отваряне на http://127.0.0.1:3001 също е отказано, защото там няма акаунт.
   Без `ADMINS` входът е изключен и всеки с достъп може да променя данните.
2. **Услуга на Windows** с [NSSM](https://nssm.cc), в PowerShell като администратор
   (сменете пътищата):

   ```powershell
   nssm install PayrollReport "C:\Program Files\nodejs\node.exe" "C:\PayrollReport\server.js"
   nssm set PayrollReport AppDirectory "C:\PayrollReport"
   nssm set PayrollReport AppStdout "C:\PayrollReport\logs\out.log"
   nssm set PayrollReport AppStderr "C:\PayrollReport\logs\err.log"
   nssm start PayrollReport
   ```

   Проверка: в `logs\out.log` трябва да пише „Вход през Tailscale. Администратори: …“.
3. **Tailscale.** Ако на сървъра вече има друго приложение зад `tailscale serve`,
   вижте какво е заето с `tailscale serve status` и изберете един от начините:

   - **собствено име `payroll`** чрез [Tailscale Services](https://tailscale.com/kb/1552/tailscale-services).
     Нужни са Tailscale 1.86 или по-нов и сървър с таг (напр. `tag:server`), а не
     вписан с потребителски акаунт. Смяната на тага сменя самоличността на сървъра,
     затова проверете дали правилата (ACL) за другото приложение още важат.
     1. В админ панела → **Services** → **Advertise** → **Define a Service**: име `payroll`,
        порт `tcp:443`.
     2. В правилата за достъп (Access controls) разрешете достъпа:

        ```json
        "grants": [{ "src": ["autogroup:member"], "dst": ["svc:payroll"], "ip": ["443"] }]
        ```
     3. На сървъра (без `--bg`, услугата работи на заден план сама):

            tailscale serve --service=svc:payroll --https=443 127.0.0.1:3001

     4. В админ панела → **Services** → `svc:payroll` одобрете сървъра (**Approve**).

     Адрес: `https://payroll.<tailnet>.ts.net`
   - отделен HTTPS порт (най-лесно, не пипа другото приложение):

         tailscale serve --bg --https=8443 http://127.0.0.1:3001

     Адрес: `https://<сървър>.<tailnet>.ts.net:8443`
   - подпът на същия адрес:

         tailscale serve --bg --set-path /payroll http://127.0.0.1:3001

     Адрес: `https://<сървър>.<tailnet>.ts.net/payroll/` (с наклонена черта накрая).

   В админ панела на Tailscale трябва да е включен HTTPS (DNS → HTTPS Certificates).
   Не използвайте `tailscale funnel`, защото прави програмата публична.

Обновяване:

    git pull
    npm ci
    nssm restart PayrollReport

## Оборотни пари

Горе вдясно се показва „Оборотни − разходи“: оборотните пари минус разходите от началото
на месеца. Остатъкът за всеки ден се вижда и в колоната „Остатък“ в Разходи.
Началната сума е 8500 и се сменя с „Промени“.

Всеки месец на 1-во число (на 2-ро, ако 1-во е неделя) програмата пита администратора
дали да нулира оборотните пари, като може да въведе нова сума. Нулирането важи от 1-во
число на месеца. Докато не се потвърди, остатъкът продължава от предишния месец.

## Колони

Имената на колоните са заключени. С „Редактирай колони“ над таблицата могат да се
преименуват, подреждат, изтриват и добавят колони.

## Данни

Всичко се пази във файла `data.json` до `server.js`: разходите, ръчните корекции на
приходите, колоните, настройките, оборотните пари с остатъка по дни и копие на продажбите по дни.

**Резервни копия.** Всеки ден програмата копира `data.json` в папка `backups\`
(`data-ГГГГ-ММ-ДД.json`) и пази последните 30 дни. Копие може да се направи и ръчно от
**Настройки**. За да възстановите копие: спрете услугата, копирайте файла върху `data.json`
и пуснете услугата отново. Добре е папката `backups\` да се копира и на друг диск.

**История.** В раздела **История** се вижда кой, кога и какво е променил (разходи, ръчни
приходи, оборотни пари, колони, настройки) и всяко четене от базата на Microinvest: за
кой период, колко реда, сума, време и грешка, ако има. Записите са в папка `history\`,
по един файл на месец.

Продажбите се изтеглят веднъж и се пазят локално; последните 3 дни се обновяват при всяко
зареждане. „Обнови от Microinvest“ изтегля наново целия показан период.

`.env` не е в `data.json`. Пазете го отделно, ако местите програмата на друг компютър.
