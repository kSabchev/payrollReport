# Отчет: разходи и приходи

Локална програма, която чете продажбите от базата на Microinvest Склад Про (SQL Server)
и ги показва по дни заедно с ръчно въведените разходи.

## Стартиране

Нужен е Node.js 20.12 или по-нов.

    npm install      # веднъж, инсталира драйвера за SQL Server (mssql)
    npm start        # работа с базата на Microinvest
    npm run demo     # демо с примерни данни, без база

Отворете http://localhost:3000.

## Структура на кода

    server.js            старт: копие при преобразуване, резервни копия, HTTP сървър
    src/
      config.js          настройки от .env
      util.js            дати, числа, текст за историята
      data.js            data.json: зареждане, преобразуване от стари версии, запис
      history.js         история на промените и четенията от базата
      backup.js          резервни копия (всеки ден в 21:05, и във втора папка)
      auth.js            акаунти, пароли, сесии
      microinvest.js     SQL заявки, групи, обекти, продажби (кеш по ден, обект и група)
      mock.js            демо данни (MOCK=1)
      stores.js          магазини, оборотни пари, отчет по дни
      stats.js           статистика (сравнения, по дни/месеци, дни от седмицата, най-продавани)
      export.js, xlsx.js отчет в Excel (.xlsx без допълнителни пакети)
      import.js          импорт на разходи от Excel (import-parse.js чете файла, xlsx-read.js — .xlsx)
      routes/            API: report, entries (разходи, приходи, оборотни), setup (настройки), auth
      http.js            HTTP сървър и статичните файлове от public/
    public/
      index.html         само разметката
      app.css            стилове (светла и тъмна тема)
      js/                скриптовете на страницата, по раздели; main.js стартира
    test/                тестове (npm test)

Скриптовете в `public/js/` са обикновени скриптове с общ глобален обхват и се зареждат в
реда от `index.html`. Тестът проверява, че заедно нямат повтарящи се имена.

## Тестове

    npm test

Тестовете пускат истинския `server.js` във временна папка (демо режим и нормален режим без
база) и проверяват отчета, разходите, оборотните пари, колоните, акаунтите, историята и
резервните копия. Не пипат `data.json` и `data-demo.json`. В GitHub се пускат автоматично
при всеки pull request (`.github/workflows/ci.yml`), а `main` приема само PR с минали тестове.

## Публикуване на демо в Render

В хранилището има `render.yaml` за Render Blueprint. Качете проекта в GitHub,
в Render изберете **New +** → **Blueprint**, свържете хранилището и приложете
конфигурацията. Render ще стартира `npm run demo`; адресът на приложението ще
се появи в таблото на услугата.

Демо режимът използва примерни данни и не се свързва с база. Всички
посетители виждат и редактират едни и същи данни. Файловата система на безплатната
услуга е временна, затова направените промени може да се загубят при рестарт или
ново публикуване. Не въвеждайте реални данни.

## Първоначална настройка

Програмата трябва да работи на същия компютър като SQL Server. Тя само чете от базата:
таблиците `Operations`, `Goods`, `GoodsGroups` и `Objects`.

1. **Потребител само за четене.** В SQL Server Management Studio изпълнете (сменете паролата
   и името на базата):

   ```sql
   USE [master];
   CREATE LOGIN [payroll_report] WITH PASSWORD = N'<силна парола>', CHECK_POLICY = ON;

   USE [<базата на Склад Про>];
   CREATE USER [payroll_report] FOR LOGIN [payroll_report];
   GRANT SELECT ON dbo.Operations  TO [payroll_report];
   GRANT SELECT ON dbo.Goods       TO [payroll_report];
   GRANT SELECT ON dbo.GoodsGroups TO [payroll_report];
   GRANT SELECT ON dbo.Objects     TO [payroll_report];
   ```

   `Objects` е списъкът с обекти (магазини). Ако потребителят вече съществува, изпълнете
   само последния ред.

   В свойствата на сървъра (Properties → Security) трябва да е избрано
   „SQL Server and Windows Authentication mode“.
2. **TCP/IP.** В SQL Server Configuration Manager → SQL Server Network Configuration →
   Protocols включете **TCP/IP** и рестартирайте услугата SQL Server. Ако инстанцията е
   именувана (напр. `SQLEXPRESS`), пуснете и услугата **SQL Server Browser** или задайте
   порта в `.env`.
3. **Файл `.env`.** Копирайте `.env.example` като `.env` до `server.js` и попълнете сървъра,
   базата, потребителя и паролата. Файлът не се качва в git и паролата не се вижда от браузъра.
4. Стартирайте с `npm start` и отворете **Настройки**. Там се вижда към коя база е свързана
   програмата. Основните групи се свързват с колоните автоматично при първата връзка:
   `AES…` → Сервиз, `AEU…` → Прима карти, `AET…` → Телефони, `AER…` → Стока. Подгрупите
   наследяват колоната на основната група по кода си. Продажбите на артикули без група
   отиват в колоната по подразбиране (Стока).

Сумите са по реалната продажна цена от документа (`Operations.PriceOut` + ДДС), включително
цените, сменени в панела за продажба.

## Инсталиране на сървъра (услуга + Tailscale)

Не отваряйте програмата към интернет. Достъпът е само през Tailscale, а самата програма
слуша само на `127.0.0.1`.

1. В `.env` задайте `PORT=3001` и `HOST=127.0.0.1` (вижте `.env.example`).
2. **Услуга на Windows** с [NSSM](https://nssm.cc), в PowerShell като администратор
   (сменете пътищата):

   ```powershell
   nssm install PayrollReport "C:\Program Files\nodejs\node.exe" "C:\PayrollReport\server.js"
   nssm set PayrollReport AppDirectory "C:\PayrollReport"
   nssm set PayrollReport AppStdout "C:\PayrollReport\logs\out.log"
   nssm set PayrollReport AppStderr "C:\PayrollReport\logs\err.log"
   nssm start PayrollReport
   ```

   Проверка: на сървъра отворете http://127.0.0.1:3001.
3. **Първи акаунт.** При първото отваряне програмата иска да създадете акаунт с име и
   парола (поне 8 знака). Направете го веднага след инсталирането. Другите акаунти се
   добавят от **Настройки → Акаунти**. Всички акаунти са администратори. Паролите се пазят
   само като хеш, а след 5 грешни опита акаунтът се заключва за 5 минути.
4. **Tailscale.** Ако на сървъра вече има друго приложение зад `tailscale serve`,
   вижте какво е заето с `tailscale serve status` и изберете един от начините:

   - **собствено име `payroll`** чрез [Tailscale Services](https://tailscale.com/kb/1552/tailscale-services).
     Нужни са Tailscale 1.86 или по-нов и сървър с таг (напр. `tag:server`), а не
     вписан с потребителски акаунт. Смяната на тага сменя самоличността на сървъра,
     затова проверете дали правилата (ACL) за другото приложение още важат.
     1. В админ панела → **Services** → **Advertise** → **Define a Service**: име `payroll`,
        порт `tcp:443`.
     2. В правилата за достъп (Access controls) разрешете достъпа:

        ```json
        "grants": [{ "src": ["autogroup:member"], "dst": ["svc:payroll"], "ip": ["443"] }]
        ```
     3. На сървъра (без `--bg`, услугата работи на заден план сама):

            tailscale serve --service=svc:payroll --https=443 127.0.0.1:3001

     4. В админ панела → **Services** → `svc:payroll` одобрете сървъра (**Approve**).

     Адрес: `https://payroll.<tailnet>.ts.net`
   - отделен HTTPS порт (най-лесно, не пипа другото приложение):

         tailscale serve --bg --https=8443 http://127.0.0.1:3001

     Адрес: `https://<сървър>.<tailnet>.ts.net:8443`
   - подпът на същия адрес:

         tailscale serve --bg --set-path /payroll http://127.0.0.1:3001

     Адрес: `https://<сървър>.<tailnet>.ts.net/payroll/` (с наклонена черта накрая).

   В админ панела на Tailscale трябва да е включен HTTPS (DNS → HTTPS Certificates).
   Не използвайте `tailscale funnel`, защото прави програмата публична.

Обновяване:

    git pull
    npm ci
    nssm restart PayrollReport

## Магазини

Всеки магазин е обект в Microinvest (`Operations.ObjectID`). Продажбите се взимат от
обекта на магазина, а разходите, ръчните приходи и оборотните пари са отделни за всеки
магазин. Колоните, групите и настройките са общи.

Магазините се добавят и сменят в **Настройки → Магазини**: име, обект и оборотни пари.
Горе вляво се избира магазин или „Всички магазини“. „Всички магазини“ показва сбора и е
само за преглед; за да въвеждате, изберете магазин. При няколко магазина всеки трябва да
има свой обект, за да не се броят продажбите два пъти.

При първото стартиране на тази версия старите данни стават един магазин „Магазин“ за
всички обекти, а копие на стария `data.json` се записва в `backups\` (`…-before-stores.json`).
Преди да добавите втори магазин, изберете обект за „Магазин“ и му дайте име.

## Оборотни пари

Горе вдясно се показва „Оборотни − разходи“: оборотните пари минус разходите от началото
на месеца. Остатъкът за всеки ден се вижда и в колоната „Остатък“ в Разходи. Всеки магазин
има своя сума (напр. 8500), която се задава в **Настройки → Магазини**, а сумата за текущия
месец се сменя с „Промени“.

Всеки месец на 1-во число (на 2-ро, ако 1-во е неделя) програмата пита администратора
дали да нулира оборотните пари, с по едно поле за всеки магазин. Нулирането важи от 1-во
число на месеца. Докато не се потвърди, остатъкът продължава от предишния месец.

## Статистика

Разделът **Статистика** показва за избрания период и магазин:

- приходи, разходи и разликата, със сравнение с предишния период и със същия период миналата
  година (текущият месец се сравнява със същия брой дни, до днес);
- приходи по колони във времето (по дни до 2 месеца, иначе по месеци), в цветовете на колоните;
- приходи − разходи по дни или месеци;
- средно на ден по дни от седмицата;
- най-продаваните артикули по сума;
- магазините един до друг (при няколко магазина).

Посочете колона за подробности. Всички числа от графиките са и в „Таблица с данните“ отдолу.

## Печат, Excel и телефон

- **Excel** изтегля отчета за показания период и магазин: Обобщение, Приходи, Разходи и
  Разни (описанията).
- **Печат** отпечатва показания раздел; в прозореца за печат изберете „Запиши като PDF“ за PDF.
- На телефон страницата се подрежда в една колона, а таблиците се превъртат настрани с
  датата закрепена вляво.

## Импорт на разходи от Excel

**Настройки → Импорт от Excel…** внася разходите за минали месеци от .xlsx файл:

- лист за всеки месец, с името на месеца („Януари“, „Февруари“…);
- на първия ред са заглавията, после по ред за всеки ден: 1, 2, … 31. Номерът на деня е в
  колона A, а ако го няма, денят се брои по реда. Редът „Sum“/„Общо“ отдолу се пропуска;
- ако има колона „Разход … (общо)“, се внасят само колоните вдясно от нея (вляво са приходите).
  Сборът ѝ се ползва за проверка: ако за някой ден не съвпада, се показва предупреждение;
- годината я няма във файла. Взема се от името на файла (напр. `ImportExcel2026.xlsx`), а в
  прозореца може да се смени;
- сумите за години преди 2026 се смятат за левове и се делят на 1,95583 (официалния курс), за да
  са в евро като останалите. Отметката „Сумите във файла са в лева“ в прозореца сменя това.

Преди записа се вижда преглед: дни и суми по месеци и по колони. Всяка колона от файла се
съпоставя с колона в Разходи. Колоните със същото име се избират сами, а останалите (напр.
„А/Д“) трябва да изберете: съществуваща колона, нова колона или „Не внасяй“. Сумите от „Разни“
се записват като един ред „от Excel“ за деня.

Дните, които вече имат разходи в програмата, се пропускат. Ако отметнете „Замени“, за тези дни
се заменят само колоните от файла, а другите остават. Преди записа се прави резервно копие
(`…-before-import.json`), а импортът се записва в **История**.

## Връзка с базата

Програмата проверява връзката с базата на Microinvest при стартиране и после на всеки 5 минути.
Ако няма връзка, горе излиза червено предупреждение и изскачащ прозорец: от кога няма връзка,
кога е последното успешно четене и причината. Разходите могат да се въвеждат и тогава, а
продажбите се показват от запазените данни. Прекъсването и възстановяването се записват в
**История**.

## Колони

Имената на колоните са заключени. В **Настройки → Колони** могат да се преименуват,
подреждат, изтриват и добавят колони.

## Данни

Всичко се пази във файла `data.json` до `server.js`: магазините, разходите, ръчните корекции
на приходите и оборотните пари с остатъка по дни (по магазини), колоните, настройките,
акаунтите и копие на продажбите по дни и обекти.

**Резервни копия.** Всеки ден в 21:05 програмата записва копие на данните в папка `backups\`
(`data-ГГГГ-ММ-ДД.json`). Ако в този час не е работила, копието за пропуснатия ден се прави
веднага при следващото стартиране. Часът се сменя с `BACKUP_TIME` в `.env`. Копията не се
трият. Копие може да се направи и ръчно от **Настройки**. Ако копие не се направи, горе в
програмата излиза червено предупреждение.

В копията няма продажбите от Microinvest (те са най-голямата част от `data.json` и винаги
могат да се изтеглят наново), затова копията са малки, въпреки че се пазят завинаги.

**Копие на друг диск или NAS.** Ако дискът се повреди, се губят и данните, и копията до тях.
Затова в `.env` може да се зададе втора папка:

```
BACKUP_COPY_DIR=\\NAS\backup\payroll
```

Всяко копие се записва и там. Ако папката не е достъпна (NAS е изключен, няма мрежа), горе
излиза предупреждение, а опитът се повтаря всяка минута. Когато папката стане достъпна,
липсващите там копия се допълват. Ползвайте мрежов път (`\\NAS\...`), а не буква на
мрежово устройство: услугата не вижда буквите, свързани от потребител.

Услугата работи като `SYSTEM` и не вижда паролата за NAS, запазена в Explorer. Затова папка,
която се отваря в Explorer, може да дава грешка „папката не е достъпна (UNKNOWN)“. Задайте
потребител и парола на NAS в `.env`:

```
BACKUP_COPY_DIR=\\NAS\backup\payroll
BACKUP_COPY_USER=потребител
BACKUP_COPY_PASSWORD="парола"
```

Програмата се свързва с `net use` при стартиране и при „Направи копие сега“. При грешна парола
не опитва отново на всяка минута, за да не заключи потребителя на NAS. Поправете паролата и
рестартирайте услугата. Ако потребителят е от домейн или NAS го иска така, пишете
`BACKUP_COPY_USER=NAS\потребител`.

Другият начин е услугата да работи с Windows потребител, който има достъп до папката (тогава
`BACKUP_COPY_USER` не е нужен):

```
nssm set PayrollReport ObjectName .\потребител парола
nssm restart PayrollReport
```

Друг вътрешен или USB диск (напр. `BACKUP_COPY_DIR=E:\PayrollBackup`) работи без това.

**Възстановяване от копие:** спрете услугата, копирайте файла върху `data.json` и пуснете
услугата отново. Продажбите се изтеглят наново от Microinvest при отваряне на отчета.

**История.** В раздела **История** се вижда кой, кога и какво е променил (разходи, ръчни
приходи, оборотни пари, колони, настройки) и всяко четене от базата на Microinvest: за
кой период, колко реда, сума, време и грешка, ако има. Записите са в папка `history\`,
по един файл на месец.

Продажбите се изтеглят веднъж и се пазят локално; последните 3 дни се обновяват при всяко
зареждане. „Обнови от Microinvest“ изтегля наново целия показан период.

`.env` не е в `data.json`. Пазете го отделно, ако местите програмата на друг компютър.
